## Что это вообще

Grizzy AI — ИИ-ассистент внутри редактора Godot. Плагин на C++ (GDExtension) добавляет в редактор панель чата. Юзер пишет запрос («добавь врага, который патрулирует платформу»), сервер ведёт агентный цикл: планирует шаги, дёргает инструменты редактора через плагин (по WebSocket), смотрит на ошибки, исправляет. Два режима: «Правка» (агент меняет проект) и «Вопрос» (только отвечает, проект не трогает).

Под капотом: FastAPI, модели через внешнего провайдера, Postgres. Админка: `https://admin.grizzy.example.com` (доступ через VPN). Стенд для тестов: `https://staging.grizzy.example.com`, тестовый ключ лежит в 1Password, в доку не тащить.

## Установка

- Нужен Godot 4.2 или новее, Windows / macOS / Linux, 64 бит.
- Качаем архив `grizzy-ai-<версия>.zip` с `https://grizzy.example.com/download`.
- Распаковать в папку проекта так, чтобы получилось `addons/grizzy_ai/` (внутри `grizzy_ai.gdextension`, `plugin.cfg`, папка `bin/`). Частая ошибка — лишний уровень вложенности `addons/grizzy_ai/grizzy_ai/`, тогда плагин не виден.
- Project → Project Settings → Plugins → включить Grizzy AI.
- Перезапустить редактор (GDExtension иначе не подхватывается до конца, панель может не появиться).
- Панель появляется справа, вкладка «Grizzy» рядом с Inspector. Хоткей Ctrl+Shift+G (на маке Cmd+Shift+G) — фокус в поле ввода.
- macOS: библиотека не подписана (нотаризация в планах). Если Godot пишет, что `libgrizzy.macos.framework` не может быть открыт, — `xattr -dr com.apple.quarantine addons/grizzy_ai` из папки проекта и перезапустить редактор.
- .NET-сборка Godot тоже работает, но агент пишет и правит только GDScript. `.cs` файлы читает, не меняет.

## Вход (обновлено, октябрь)

Старый способ (до 0.9): юзер копировал API-ключ из личного кабинета на сайте и вставлял в Settings → API Key. Ключ хранился в `user://grizzy_auth.json` открытым текстом, за что нас справедливо пинали.

Новый способ — OAuth device flow через единый аккаунт Bear Head Studio:

1. В панели жмём «Войти».
2. Панель показывает код из 8 символов (вида `WDJB-MJHT`) и открывает браузер на `https://account.example.com/device`.
3. Входим в аккаунт Bear Head Studio (или регаемся), вводим код, жмём «Разрешить».
4. Панель сама подхватывает вход в течение пары секунд.

Код живёт 15 минут, потом надо нажать «Войти» заново. Плагин хранит короткий access-токен и refresh-токен в системном хранилище (Keychain на macOS, Credential Manager на Windows, libsecret на Linux), а не в файле. Выйти — Settings → «Выйти из аккаунта».

Старый вход по ключу пока оставили параллельно (поле «API key (устарело)» в настройках), выпилим в 0.10.

## Кредиты

Расход в кредитах. Списываем после ответа модели по количеству токенов (вход + выход). Если соединение оборвалось посреди хода, токены уже потрачены и не возвращаются — это известная боль.

При регистрации дают 100 приветственных кредитов. Баланс — в панели внизу и в личном кабинете.

Средний ход на простой запрос — 3–8 кредитов, на сцену с кучей узлов может быть 20+.

## Инструменты агента

| Инструмент | Что делает |
|---|---|
| `list_files` | список файлов проекта (с учётом политики доступа) |
| `read_file` | читает файл, лимит 200 КБ |
| `search_project` | поиск по тексту в `.gd`, `.tscn`, `.tres` |
| `get_scene_tree` | дерево открытой или указанной сцены: узлы, классы, скрипты, `@export` |
| `add_node` | добавляет узел в сцену |
| `set_property` | меняет свойство узла |
| `connect_signal` | подключает сигнал |
| `write_script` | создаёт или перезаписывает `.gd` |
| `delete_file` | удаляет файл. Без подтверждения, так что осторожнее с формулировками вида «убери лишнее» |
| `run_scene` | запускает сцену без окна на 5 секунд и возвращает ошибки |
| `get_errors` | ошибки из панели «Вывод» и парсера скриптов |

Правки сцены за один ход — одно действие в Undo (Ctrl+Z откатывает весь ход агента в этой сцене). Запись скриптов в Undo не попадает.

## Лимиты

- Максимум 20 шагов агента за один ход, дальше ход останавливается с сообщением «Достигнут лимит шагов». Обычно значит, что запрос слишком большой — лучше разбить.
- `read_file` — до 200 КБ на файл.
- Сцены больше ~2000 узлов агент видит не целиком (обрезаем контекст).
- Ранний доступ: не больше 30 ходов в час на аккаунт.

## Настройки

Settings в панели (шестерёнка):

| Параметр | По умолчанию | Что делает |
|---|---|---|
| Модель | Grizzy Fast | Fast — дешевле и быстрее, Pro — лучше на сложных запросах, дороже |
| `max_steps` | 30 | сколько шагов агент может сделать за ход, от 5 до 50 |
| Подтверждать правки сцены | выкл | если вкл — агент показывает план и ждёт «Применить» |
| Язык ответов | как в запросе | |
| Файл политики | `res://.grizzy/policy.json` | см. ниже |

## Политика доступа к файлам

Агент работает только внутри папки проекта (`res://`). Выйти наружу (`../`, абсолютные пути) не может ни при каких настройках.

`res://.grizzy/policy.json` — что агенту можно читать и писать:

```
{
  "read":  ["**/*"],
  "write": ["scenes/**", "scripts/**"],
  "deny":  ["secrets/**"]
}
```

Есть жёсткий список запретов, который политикой не отключается: `.git/`, `.godot/`, `.env` и `.env.*`, `*.key`, `*.pem`, `addons/grizzy_ai/`. Даже если юзер явно разрешил — агент такие файлы не увидит.

## Известные проблемы

- Агент иногда пишет код под Godot 3 (`yield`, `KinematicBody2D`, `export var`). Обычно сам ловит через `get_errors` и чинит со второго шага. Если нет — дописать в запрос «проект на Godot 4.4».
- За корпоративным прокси WebSocket может не пробиться: панель пишет «Нет соединения с сервером». Нужен доступ к `wss://api.grizzy.example.com` на 443.
- Windows: после перезапуска редактора пропадала история чата (починили?).
- На macOS см. карантин выше.
- Локальные модели и свой API-ключ провайдера не поддерживаем и пока не планируем.
- Unity / Unreal — в планах, сроков нет. Облачный режим (правка игры в браузере без установки Godot) — исследуем, есть лист ожидания на сайте.
